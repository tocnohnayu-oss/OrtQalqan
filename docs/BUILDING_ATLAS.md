# Здание: 3D-модель, слои и быстрый поиск

26.10.2026. Пользователь попросил глобальное обновление и затем прямо отверг раскладку бумажных этажей: нужна цельная модель, которую можно вращать. Текущий интерфейс — **реальная WebGL-сцена на Three.js 0.186.1**, а не CSS-перспектива листов.

## Маршрут и данные

Главная навигация: **Здание / План / Обход**. Первый вид — здание; предпочтение устройства `ortqalqan.workspace.view=atlas|floor` содержит только выбор рабочего масштаба. Building/SQLite/резервный JSON не менялись. Подробный план остаётся смонтированным скрыто для сохранения его камеры; `.studio-layout[hidden]` исключает его из отображения и клавиатурного порядка.

Здание показывает только существующие Floor.layout. Помещения, коридоры, ортогональные вогнутые контуры, двери и окна берутся из введённой геометрии. Изображение без контура не превращается в стены. Этаж без геометрии не получает вымышленного корпуса; видны счётчик этажей с контуром и возможность открыть обычный план/конструктор.

Этажи совмещаются по координатам исходных чертежей. Начальная высота — **условные 3 м**, меняется в параметрах вида в пределах 2–6 м. Высота, толщина стены 0,16 м, перекрытие 0,14 м и вертикальные размеры проёмов — параметры визуализации, не обмер и не норматив. Они не переносятся в расчёт, площадь или сохранённый объект. Отсутствующие этажи сохраняют свои индексы по высоте, но их геометрия не придумывается. Это не BIM-модель и не фактическая реконструкция НИШ.

## Реальная объёмная сцена

`domain/building-model.mjs` строит физические отрезки стен. Совпадающие и частично общие границы разбиваются на интервалы и объединяются. Проём одной из соседних комнат прорезает общую стену один раз. Ширина проёма/положение берутся из openingGeometry; окна без исходной записи не генерируются.

`scene/building-scene.mjs` создаёт Three.js WebGLRenderer, PerspectiveCamera, OrbitControls, объёмные стены/перекрытия/кровлю, стекло и двери. В цельном виде видны наружные стены и кровля; в разрезе верхние этажи скрываются, выбранный этаж открыт, стены срезаны примерно на 1,15 м для обзора помещений. Нижние этажи сохраняют оболочку. Условная 3D-обстановка использует прямоугольники прежнего furniturePrimitives и явный preset; это не реальная инвентаризация.

Типовые параллелепипеды стен/рам/дверей/обстановки объединяются в InstancedMesh. Контуры перекрытий и кровли экструдируются по настоящему полигону, не по его bounding rectangle. Свет, затенение и перспектива рендерятся в WebGL. Canvas не вращается CSS-трансформацией.

Управление: мышь/один палец — вращение, колесо/два пальца — масштаб, правая кнопка или модификатор — перенос. Есть явные кнопки поворота, масштаба, вида сверху и общего вида. Стрелки вращают, +/− масштабируют, 0/Home возвращают общий вид. Случайный выбор помещения после drag/pinch блокируется.

Общий вид подбирается по проекции восьми углов настоящего bounding box с учётом пропорций viewport. Изменение размеров окна/переход к разрезу сохраняют направление камеры и вписывают видимую модель. Свободное вращение не меняет данные объекта. По нажатию выбирается этаж/помещение; карточка выбранной комнаты открывает её прежние параметры. Каталог доступен и без взаимодействия с 3D.

Сцена загружается отдельным динамическим чанком только при наличии контуров. При неподвижной камере нет постоянного анимационного цикла; OrbitControls запрашивает кадры при движении/затухании. При prefers-reduced-motion затухание отключено. ResizeObserver и все обработчики снимаются при закрытии; геометрии, материалы, текстуры и WebGL-контекст освобождаются. Ошибка/потеря контекста показывает повторный запуск и оставляет обычный план доступным.

## Слои и следующий шаг

`domain/building-atlas.mjs` остаётся независимым от Three.js. «Помещения / Осмотр / Расчёт» связаны с подробным планом. Сохранённый осмотр, известное наблюдение/срок и неизвестные данные различаются. Дата — Building.date, она видна в заголовке и подписи слоя. Прежняя checkedOn не становится сегодняшним завершением. Число записей осмотра не является процентом безопасности.

ОП/ОУ/manual берутся только из актуального Snapshot с совпадающими Building.id/revision. После изменения данных старые типовые цвета и количества скрываются. Цвет не задаёт место установки или покрытие. Общие пространства без zoneId не получают чужой расчёт.

В разрезе цвет виден на полах/стенах помещений. В цельном здании кровля закрывает интерьер — для внутреннего обзора используется явный разрез. На обычном плане сохраняются data-map-state и адаптивные PlanLabels с текстовым смыслом состояния. Конструктор, SVG и PDF используют прежнюю геометрию; 3D-вид не подменяет документ.

Продолжение обхода использует прежний resumeInspection. Лист внимания открывается сразу через initialView. Переход не отмечает помещение осмотренным. Кнопка пустого этажа открывает редактор именно выбранного Floor.id.

## Учебный пример

Кнопка в пустом обзоре явно создаёт отдельный трёхэтажный корпус: библиотека/лаборатория, восемь учебных/служебных зон второго этажа и спортзал/раздевалки третьего. Все layouts имеют example=true, площади согласованы с контурами, завершённых осмотров нет. Это авторские учебные данные без адреса НИШ/реальных людей. Старые объекты и защита несохранённого общего объекта сохраняются. Пример экскурсии остаётся отдельным одноэтажным сценарием 3 ОП/1 ОУ.

## Быстрый поиск

Кнопка поиска и Ctrl/⌘ K открывают native dialog. Поиск работает только с текущим Building через findRooms: RU/KK, этаж, номер/модель. NFKC/регистр/ё/тире применяются только к индексу. До 40 результатов с предложением уточнить; одинаковые номера разных Asset.id не сливаются.

Стрелки/Enter, мышь и touch открывают один и тот же источник. Escape явно закрывает поисковый лист, а не только очищает type=search. Фокус возвращается к открывшему элементу, включая SVG/canvas; возврат завершается после отложенного восстановления развёрнутого плана. Комната получает фокус на полном заголовке. Оборудование раскрывается в прежнем реестре с подсветкой номера без автоматического редактирования.

Сочетание не открывает второе окно поверх dialog/экскурсии. Прежние подтверждения несохранённого редактора и оборудования действуют. Запрос и данные общих объектов не записываются в localStorage; автоматической отправки/сохранения группы нет.

## Проверки и инфраструктура

75 доменных тестов включают реальные/отсутствующие контуры, источник/ревизию снимка, неподдержанную методику, даты/неизвестные данные, трёхэтажный пример, общие стены, проём с одной стороны, исходную ширину окна и независимую высоту 3D.

`scripts/building-atlas-smoke.mjs` проверяет настоящий WebGL 2, наличие meshes, изменение камеры и изображения после drag, клавиатуру, разрез/высоту, отсутствие экструзии изображений, 320px KK и настоящий CDP pinch. Также проверяются прежняя камера 2D, Ctrl K/Enter/Escape, одинаковые номера разных этажей, stale, reload, каталог 30 пустых этажей и создание отдельного примера. Остальные smoke продолжают проверять редактор, аккаунты, обход, источники и PDF.

CI закреплён на ubuntu-24.04 и использует поддержанный Playwright channel `chrome`, предустановленный в runner. Браузерная установка с OS-зависимостями зависала; тесты переведены на уже доступный Chrome. Версия/канал записаны в checks.json. Только CI включает --enable-unsafe-swiftshader для настоящего WebGL на стенде без GPU. Локальный smoke по умолчанию использует bundled Chromium. `npm ci` сохраняет committed lock и не меняет checkout перед публикацией синтетических снимков.

Локально сеть npm ограничена. Для сборки официальные Three build/OrbitControls восстановлены из gitHead опубликованной 0.186.1; blob SHA совпали: core 0a1d6cb9ef3cabc97a50bd02394c85e8d1c513c2, module c52087acfabae80efabb8cc05e3a1d96e35a1426. В Git входят только package.json/lock с официальной npm integrity. Node_modules не коммитится; обычная установка — npm install.

Первичные источники: [Three.js OrbitControls](https://threejs.org/docs/pages/OrbitControls.html), [ExtrudeGeometry](https://threejs.org/docs/pages/ExtrudeGeometry.html), [официальный выпуск npm](https://registry.npmjs.org/three/latest), [Ubuntu runner](https://github.com/actions/runner-images/blob/main/images/ubuntu/Ubuntu2404-Readme.md#browsers-and-drivers), [Playwright channels](https://playwright.dev/docs/browsers#google-chrome--microsoft-edge). Принципы этажного контекста и слоёв изучались по [ArcGIS Field Maps](https://doc.arcgis.com/en/field-maps/ios/use-maps/quick-reference.htm); код/айдентика самостоятельные. Экспертная проверка методики и наблюдение за реальным инспектором остаются внешними шагами.
