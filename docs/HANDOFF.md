# Текущее состояние OrtQalqan

Обновлено 24.10.2026. Прочитать `AGENTS.md`, затем этот файл. Геометрия и готовые блоки — `FLOOR_EDITOR.md`, обход — `FIELD_WORKFLOW.md`.

## Последние требования пользователя

Последняя просьба — «ещё круче делай»: продолжать улучшать дизайн автономно, проверяя удобство самому. После архитектурной шапки/графики видов здания развита сама рабочая поверхность: развёрнутый план с возвратом к объекту, более наглядный каталог конструктора, чернильный активный инструмент и повороты рядом с чертежом. Светлая тема полевого атласа, минимализм и графический приоритет сохранены. См. `BRAND.md`, `FLOOR_EDITOR.md`, `styles/plan-workspace.css`.

Сохраняемые требования:

- Инспекторы ЧС; телефон и компьютер; полный RU/KK, включая PDF. Детали по выбору комнаты, без новых постоянных сводок и множества карточек.
- Разные типы здания. НИШ ЕМН Петропавловска — один синтетический пример, а не обследование школы. Подтверждены только её название/адрес; фактического поэтажного плана нет. Автоматическую вымышленную архитектуру НИШ не возвращать.
- Тематические готовые блоки с условной мебелью, размеры, соединение с коридором и поворот. Загрузка своего изображения остаётся отдельным режимом. Тёмный штрих старого логотипа убран; щит/пламя сохранены.
- Явная кнопка смены объекта, подписанный вход/имя и доступная инструкция. Учебный корпус открывается отдельной копией; «Рассчитать» показывает обоснование из Snapshot и PDF. Сценарий защиты — `DELIVERY.md`.
- Собственные почта/пароль, рабочие группы, ответственные и общая SQLite база. В Vite dev/preview API работает на том же порту; отдельный процесс 8787 не требуется. Production запускается через `npm start`. Общего размещённого сервера пока нет.
- Markdown-контекст для команды; не выдавать технические проверки за экспертную верификацию расчётной методики.

## Что работает

- «Развернуть план» сохраняет текущий режим, камеру и данные на рабочем листе на всю область окна. Имя объекта/учебная маркировка и «К объекту» остаются видимы. Escape сначала обрабатывает вложенное окно/подтверждение, выход возвращает прокрутку и фокус.
- На телефоне поиск помещений раскрывается отдельной кнопкой, после выбора сворачивается. Параметры открываются прежним листом; закрытие возвращает фокус к плану. Изображение не растягивается и сохраняет процентные координаты меток.
- Каталог конструктора: крупные миниатюры, архитектурный заголовок, акцент типа выбранного блока. Повороты находятся у выбранной комнаты рядом с масштабом, цели на телефоне 44 px. Сохранение из развёрнутого изображения возвращает к изменённому чертежу внутри того же рабочего режима.
- Архитектурная шапка: ObjectSketch для шести типов, тип объекта (без дублирования названия), крупный заголовок, явная смена объекта. Длинное название показано полностью, более компактным кеглем на узком экране. Логотип щита/пламени сохранён.
- Активный этаж — чернильная вкладка со светлой подписью; desktop-заголовок листа повторяет порядковый индекс. На телефоне вспомогательные цифры навигации/заголовка скрыты. Фон нейтральный #EAE8E1, вместо одинаково бледных зелёных поверхностей.
- Пустой план: новая композиция с тематическими помещениями и карандашом, общая условная обстановка RoomFurniture. У разных зданий разные мотивы. Иллюстрация не создаёт Floor.layout и не изображает фактический план/фасад.
- Исправлена планшетная раскладка: до 1050 px параметры идут листом под планом на всю ширину; исчезли пустая колонка и неверная внутренняя grid-сетка. SVG/PDF сохранили геометрию и получили чуть более контрастные линии обстановки.


- Поиск внутри листа этажа: RU/KK, этаж, название, номер/модель оборудования. Только текущий объект. Результаты сгруппированы по этажам; одинаковые номера не сливаются. Сначала 30 совпадений с явным продолжением, прокрутка не растягивает план. Escape очищает запрос и сохраняет фокус.
- Найденное помещение открывает свой этаж/параметры; отсутствие чертежа не создаёт геометрию. Найденное оборудование открывает реестр без редактирования, с подсветкой, фокусом и видимыми этажом/комнатой. Закрытие возвращает фокус в поиск, «Открыть на плане» — к плану.
- Обход из шапки продолжает начатые ответы, затем неосмотренные комнаты; из параметров открывает конкретную комнату. Следующий шаг учитывает поиск/фильтр. Обзор внимания включает завершённые записи с замечаниями и останавливается в конце.


- Просмотр плана: мышь/один палец перемещают, pinch и Ctrl/Cmd + колесо масштабируют с сохранением точки жеста. Стрелки, +/− и 0/Home, отдельные кнопки выбранной комнаты и всего этажа. Drag/pinch не открывают параметры случайно. Камера не меняет геометрию/расчёт. На телефоне новая выбранная комната автоматически приближается.
- Общий для телефона/компьютера переключатель ОП/ОУ под планом: свежие количества из Snapshot, явный подбор для неподдержанных зон, скрытие прежних чисел после правок. Площадь подписи комнаты по-прежнему относится к чертежу; при отличии от расчётной площади обе показаны в результате. Подписи не являются позициями установки.
- «Изменить» у каждой зоны в результате открывает текущие параметры, переключает этаж и фокусирует площадь. На телефоне открывается лист параметров. Из устаревшего снимка переход недоступен до обновления.


- Обучение: пять шагов с подсветкой реальных контролов, RU/KK, Escape, пропуск и повторный запуск, возврат фокуса/прокрутки. Только seen-предпочтение сохраняется в localStorage; ссылка приглашения не перекрывается welcome.
- Явный учебный корпус отдельной копией: готовые библиотека/класс/серверная/лаборатория и коридор. Без регистрации и подмены геометрии НИШ. Изменения существующего общего объекта не записываются этим действием; прежнее подтверждение несохранённого черновика действует.
- После явного расчёта видны ОП/ОУ, area/rate/count с округлением, поддержанные/ручные зоны, наличие из формы и источники. Если введённая площадь отличается от геометрии, показаны оба значения и источник расчёта. UI не реализует другое правило. PDF строится из того же Snapshot.

- Собственные регистрация/вход/выход, несколько рабочих групп, роли coordinator/inspector, одноразовые приглашения на 7 дней. Общий архив объектов с ответственными, этапами, фильтрами и журналом реальных событий. Только координатор меняет назначения/этапы и приглашения.
- Общий объект сохраняется отдельной кнопкой; версия базы защищает от потери конкурентных изменений. При конфликте предлагаются JSON своей копии и явная загрузка версии базы. Объекты аккаунта не пишутся в локальную библиотеку; выход восстанавливает черновик устройства.
- Упрощённая шапка: объект, расчёт, PDF. Этажи/зоны и план в рабочей области. Панель параметров появляется после выбора. История, сценарии и справка находятся в «Ещё».
- Последний визуальный слой — `atlas.css`: Roboto Condensed для заголовков/индексов, Noto для рабочего текста/PDF, чёткие листы и вкладки, оригинальная иллюстрация пустого плана. Оба шрифта локальные, лицензии в `public/fonts`, cmap включает все казахские буквы. Обход на телефоне полноэкранный; основной экран остаётся простым.
- Убраны большой декоративный корпус, метрики отдельной полосой, полоса прогресса на главной, плавающий итог и постоянная нижняя панель. Знак — щит с пламенем, без диагонали Q.
- Пустой план вместо автоматической архитектуры. Имеющиеся расчётные зоны остаются в списке. Старый `Diagram.tsx` больше не используется.
- Конструктор: готовые наборы для школы, офиса, магазина, склада, производства и другого здания. Блок добавляется перетаскиванием, нажатием или Enter. Есть ручной прямоугольник/ортогональный контур как дополнительный способ.
- Автоматическая обстановка: класс, библиотека, лаборатория, спортзал, офис, переговорная, серверная, торговля, хранение, производство, лестница, санузел. Символы подстраиваются к размеру. Это не инвентаризация и не расчёт вместимости.
- Изменение размеров/координат, перенос, угловые точки с увеличенной областью захвата, сетка 0,25 м, точный ввод числом, pan/zoom/fit, 50 шагов undo/redo.
- Поворот влево/вправо на 90°, R/Shift+R вне полей. Поворачиваются обстановка и проёмы, названия остаются горизонтальными. Пересечение соседних помещений отклоняется с причиной.
- Двери/окна с шириной, петлёй и направлением открывания. Типовой блок автоматически получает проёмы; при фактическом примыкании к коридору дверь размещается на общей стене. Ручное изменение проёмов отключает дальнейшую автоматическую перестановку для этой комнаты.
- Геометрия сохраняется отдельным применением редактора. Удаление формы не удаляет расчётную зону. Площадь переносится в расчёт только отдельным выбором; геометрия сама не меняет пожарные характеристики.
- Самостоятельный SVG и векторный лист построенного этажа в PDF, включая условную обстановку. Старые PDF-карточки, изображавшие схему, убраны.
- PNG/JPG/WebP до 2 МБ и метки ОП/ОУ остаются отдельным режимом. Нет автоматического распознавания или проверки расстояний.
- Понятный обход: одно помещение, три radio-группы «В порядке / Есть замечание / Не относится», неизвестный ответ до выбора, число оставшихся проверок, одна кнопка сохранения/перехода. Замечание остаётся после завершения записи.
- На телефоне список помещений обхода свёрнут. Подробные наблюдения и оборудование раскрываются по необходимости. При переходе фокус возвращается к названию комнаты. Из шапки можно обновить снимок и открыть отчёт.
- Реестр до 100 единиц на зону: номер, модель, ОП/ОУ, состояние, введённая паспортная дата обслуживания. 30 дней — окно планирования, не нормативный интервал. Реестр не меняет ручное `existing`.
- Библиотека до 20 независимых объектов; шесть структур без вымышленных площадей и классов. Шесть симуляций с отдельным применением, JSON, CSV, история шести расчётов сессии и PDF RU/KK.

## Модель и хранение

`Floor.layout` необязателен: версия 1, rooms/openings/example?. Контуры ортогональные, 4–40 вершин, координаты ±200 м. До 120 форм/100 расчётных зон/400 проёмов. Внутренние пересечения и наложение проёмов отклоняются; общие стены разрешены. Каждая зона связана максимум с одной формой. Коридор/лестницу можно сделать общим пространством без zoneId.

`LayoutRoom.preset`, rotation 0/90/180/270 и autoOpenings управляют обозначениями. Они не назначают пожарный класс. `Zone.area` остаётся независимой до явного переноса. Старые JSON без layout поддерживаются.

Ключ localStorage `ortqalqan.building.v1`, обёртка v2: `{version:2,activeId,buildings:[...]}`. Старый v1 читается. Резервный JSON одного объекта остаётся v1. Все объекты записываются одним значением, без дублирования картинки активного плана. Ошибки квоты видны. Это библиотека гостевого режима. Объекты группы хранятся отдельно в SQLite, с явным сохранением и проверкой версии; автоматической синхронизации и автономной установки нет. Общий сервер ещё не размещён. История расчётов — текущая сессия.

Аккаунты: `users/workspaces/memberships/sessions/objects/invitations/events`. Данные БД по умолчанию в `var/ortqalqan.sqlite`, не включать в Git/артефакты. Для сохранения данных между перезапусками сервера нужен постоянный диск. Node.js 24.14+. Почта пока не подтверждается, нет восстановления/смены пароля и MFA; подробности и границы прототипа в `ACCOUNTS.md`.

Профиль `public-pilot-2026-10-23` предварительный, общественные помещения A/E. Пропорциональный расчёт/округление, связь исторической ссылки с актуальными Правилами и типоразмер ОУ требуют экспертной проверки. См. `NORMATIVE_RESEARCH.md`.

План, завершённая запись осмотра, количество и дата обслуживания не доказывают соответствие. Редактор не вычисляет маршруты, покрытия, эвакуацию или фактические расстояния. Диагональные стены, отверстия внутри комнаты и 3D сейчас не поддерживаются. Ревью настоящим инспектором/экспертом не проведено.

## Среда

`/home/tocnohnayu/OrtQalqan`, `npm run dev` в обычном терминале пользователя запускает Vite со встроенным настоящим API/SQLite на 127.0.0.1:5173. Отдельный API на 8787 не запускать. /api/health должен вернуть ready: true. Прямой vite и preview тоже подключают API. Старый процесс Vite нужно остановить и перезапустить новой командой. `npm start` обслуживает dist и API на 8787; внешний HTTPS origin и постоянный диск задаются через env. Vite обновляет интерфейс при изменениях. В sandbox HTTP/Chromium ограничены; браузерная проверка выполняется в GitHub Actions.

GitHub обновляется через подключённое приложение с проверкой текущего SHA. Локальный `.git` после Sites helper без исходного коммита; не делать слепой local push. Не перезаписывать чужие удалённые изменения.

Sites ID в `.openai/hosting.json` сохраняется. Owner-private, версия 0, публикации нет. Попытка синхронизации снова завершилась DNS-ошибкой `git.chatgpt-team.site`. Второй Sites не создавать и ожидаемый адрес не выдавать за live.

## Следующие внешние шаги

Отзыв пользователя и наблюдение за инспектором, экспертная проверка методики, реальные планы/измерения конкретного объекта. Для пилота — фото, документальная история ТО, привязка инвентарного номера к метке и синхронизация. Для общего доступа разместить Node сервер с SQLite на постоянном диске и HTTPS. У существующего Sites сохранён ID, но Node backend нельзя выдать за работающую базу статической публикации; для Sites понадобился бы отдельный перенос серверного адаптера/хранилища.
