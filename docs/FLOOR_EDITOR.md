# Редактор этажа и упрощение экрана

Дата: 24.10.2026. Пользователь попросил убрать странный штрих логотипа, упростить перегруженный интерфейс и заменить нереалистичный автоматически придуманный чертёж удобным конструктором.

## Рабочий экран

На экране остаются объект, этажи, помещения и план. Параметры открываются после выбора помещения. Крупная иллюстрация корпуса, метрическая сводка, отдельная полоса прогресса обхода, плавающий итог и постоянная мобильная панель убраны. Расчёт и PDF находятся в шапке объекта. История, сценарии и справка — в «Ещё».

Новый объект и старый объект без геометрии начинают с пустого плана. Расчётные зоны доступны в списке, их данные не теряются. Старый `Diagram.tsx` больше не используется в интерфейсе. Его автоматически нарисованный корпус не мигрируется в фактическую планировку. Для НИШ нет подтверждённой поэтажной геометрии.

Тёмная диагональ Q убрана из знака и favicon. Остаётся щит с пламенем.

## Основной способ: готовые блоки

Пользователь уточнил, что план должен собираться перетаскиванием готовых блоков по типу здания. Это теперь основной способ. Для школы есть класс, библиотека, лаборатория, спортзал, серверная, коридор, лестница и санузел; для других типов — свои наборы. Клик/Enter по блоку добавляет его рядом с планом как альтернатива перетаскиванию.

`LayoutRoom.preset` хранит явный тип обозначений. Обстановка генерируется автоматически и подстраивается под размеры: парты/доска, стеллажи, лабораторные столы, спортивная площадка, офисные столы, стойки, паллеты. Это условные символы, не обследованный состав мебели и не расчёт вместимости. Количество символов ограничено, чтобы большой зал не порождал тысячи элементов.

Новый блок по возможности связывается с ещё не нанесённой одноимённой зоной; её параметры сохраняются. При отсутствии подходящей зоны создаётся новая с неизвестными характеристиками. Название/обстановка не назначают пожарный класс.

Типовые двери/окна имеют `auto:true`. Если помещение примыкает к коридору по общей стене, дверь размещается на общей стене. Далёкие блоки не соединяются невидимым проходом. Ручное редактирование проёмов отключает их дальнейшую автоматическую перестановку для этого помещения. Изменение размеров не требует вручную передвигать каждую парту.

Обозначения включены в самостоятельный SVG и векторный PDF через общий модуль `furniture.mjs`. На телефоне набор горизонтальный: блок можно добавить нажатием; для перетаскивания используется его графический значок. Ручной контур остаётся дополнительным способом.

## Сценарий редактора

1. «Создать план» открывает временный черновик выбранного этажа.
2. «Помещение» рисуется перетягиванием между углами. В панели можно выбрать существующую расчётную зону, новую зону либо общее пространство без расчёта.
3. «Контур» позволяет указать последовательность углов Г-образной и другой ортогональной формы. Последний участок замыкается кнопкой или Enter.
4. Помещение перемещается целиком. Угловые точки меняют форму, сохраняя прямые углы. Размеры и координаты доступны числами — это альтернатива перетаскиванию.
5. Дверь/окно ставится нажатием на стену. Меняются ширина, петля и направление открывания. Это параметры чертежа, не автоматический нормативный подбор проёмов.
6. Undo/redo хранит до 50 состояний текущей сессии редактора. Ctrl/Cmd+Z и Delete действуют вне текстовых полей.
7. «Сохранить план» применяет черновик к этажу одной операцией. Уход с несохранёнными изменениями требует решения пользователя.

Пример в справке редактора — отдельное явное действие. Он помечается `example:true`, не называется планировкой реального здания. Сам по себе пример не меняет расчётные площади.

## Геометрия и площади

`Floor.layout` необязателен: `{version:1,rooms,openings,example?}`. Каждое помещение содержит id, необязательный zoneId, названия RU/KK и контур в метрах. Одна расчётная зона связана максимум с одним контуром. Проход/коридор можно оформить общей зоной без zoneId.

Контур задаёт границу введённой площади. Толщина нарисованной стены — оформление, не введённая толщина конструкции. Площадь вычисляется формулой многоугольника; отверстия и наклонные стены сейчас не поддерживаются. Не называть редактор полноценной CAD/BIM-системой.

Сетка 0,25 м. Числа можно вводить точнее сетки. Контуры ортогональны, без самопересечений, минимум 4/максимум 40 вершин, координаты от −200 до 200 м. Общие стены допускаются, пересечение внутренних площадей отклоняется. Для вогнутых контуров используется разложение на внутренние прямоугольные полосы, а не простое сравнение bounding boxes.

Двери/окна принадлежат ребру и хранят положение относительно длины стены. При изменении стены проём сохраняет ширину. Если он не помещается, изменение отклоняется; два проёма на одном участке стены не накладываются.

**Геометрия не входит в пожарный расчёт автоматически.** Пользователь отдельно выбирает «Перенести площади по размерам в расчёт». Без этого старые площади сохраняются, у новой зоны площадь 0 и класс требует уточнения. Обычная зона не получает пожарный класс из названия/формы.

Удаление формы не удаляет расчётную зону. Удаление расчётной зоны в форме параметров удаляет её форму/проёмы и метки изображения, сохраняя валидность данных.

## Хранение и экспорт

План входит в локальную библиотеку, JSON и снимок расчёта. Старые файлы без layout поддерживаются. Валидация импорта проверяет геометрию, ссылки, пределы, дубли и проёмы. Любые правки сохранённого чертежа делают PDF-снимок устаревшим, даже если расчётная площадь не менялась.

SVG экспортируется как самостоятельный векторный файл с экранированием пользовательского текста. PDF получает отдельный векторный лист каждого построенного этажа. Воображаемая схема карточек из предыдущего PDF убрана. Загрузка PNG/JPG/WebP и разметка изображения остаются отдельным режимом; распознавания/автоматической калибровки изображения нет.

План не вычисляет нормативные пути, расстояния покрытия, эвакуацию или соответствие здания.

## Поворот блока

По следующей просьбе пользователя добавлены повороты влево/вправо на 90° и R/Shift+R вне полей. Поворачиваются вершины, обстановка и связанные проёмы. Названия сохраняются горизонтальными. Пересечение с соседним помещением отклоняется с объяснением. Площадь сохраняется; пожарные параметры не меняются. `LayoutRoom.rotation` поддерживает 0/90/180/270.

Поворот учитывается общим генератором условной мебели: SVG и PDF используют тот же transform. У автоматических проёмов сохраняются стороны блока; общая стена с коридором имеет приоритет для входа. Наклон на произвольный угол пока не поддерживается — только четвертьобороты, сохраняющие ортогональность.

## Навигация при просмотре

Просмотр построенного этажа поддерживает pan, pinch, Ctrl/Cmd + колесо и клавиатуру (стрелки, +/−, 0/Home). Движения меняют только камеру, не Floor.layout/Zone.area. Математика `view-navigation.mjs` учитывает поля SVG xMidYMid meet, сохраняет точку жеста и пропорции на предельном масштабе. Захват указателя удерживает жест за границей комнаты; pinch/drag не превращаются в выбор помещения.

Под планом общие для телефона и компьютера кнопки: количество ОП/ОУ, приблизить выбранное, −/+, весь этаж. Количества берутся только из актуального Snapshot, не означают размещение и не включают неподдержанные зоны как нулевые. Готовые позиции оборудования автоматически не создаются.

Технические источники: [MDN Pointer Events pinch](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events/Pinch_zoom_gestures), [MDN setPointerCapture](https://developer.mozilla.org/en-US/docs/Web/API/Element/setPointerCapture), [Playwright CDPSession](https://playwright.dev/docs/api/class-cdpsession). Реальные touch-события Chromium и переход к другой зоне/этажу проверяет `scripts/navigation-smoke.mjs`.

## Развёрнутый лист и контекстные инструменты

«Развернуть план» оставляет тот же план и камеру в окне на всю рабочую область. Это режим интерфейса на CSS viewport, без запроса Browser Fullscreen API. Шапка сохраняет имя объекта и маркировку учебного примера. «К объекту»/Escape возвращают прокрутку и фокус. Escape сначала обрабатывает открытый native dialog/подтверждение редактора; незавершённый черновик не теряется. Поиск в текстовом поле по-прежнему очищается отдельным Escape.

На телефоне список комнат свёрнут, этажи остаются доступны; кнопка поиска раскрывает индекс. Выбор комнаты складывает индекс, параметры открываются прежним листом. После закрытия фокус возвращается к плану. План-изображение сохраняет режим и процентные координаты меток; контейнер прокручивается, изображение не обрезается через object-fit.

Каталог редактора продолжает айдентику атласа: архитектурная метка вида объекта, крупные планы блоков, чернильный выбранный инструмент, акцент типа выбранной комнаты. Подсветка типа не является учётом количества помещений. Повороты перенесены из прокручиваемых свойств к выбранной комнате рядом с масштабом; используются прежние rotateRoom/updateRoom, undo и проверки пересечений/проёмов. R/Shift+R объявлены через aria-keyshortcuts.

Стили находятся в `styles/plan-workspace.css`, подключённом после atlas/proof. `FocusPlanHeader` и состояние App не меняют модель хранения. Проверка `scripts/focus-plan-smoke.mjs` использует настоящие жесты и native dialogs, проверяет возврат камеры/фокуса, отмену редактора и сохранность координат изображения. Сохранение из развёрнутого изображения возвращает к изменённой схеме: добавленный/повёрнутый блок сохраняется после перезагрузки, существующие ручные площади остаются прежними, новая расчётная зона не заполняется размерами чертежа. Режим просмотра после перезагрузки обычный.

Первичные ориентиры: [Floorplanner](https://floorplanner.com/) — библиотека помещений рядом с рабочей поверхностью; [MDN requestFullscreen](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen) — ограничения браузерного полноэкранного API. Наш выбор viewport-режима обеспечивает одну реализацию для телефона и компьютера и не заявляет 3D/распознавание или нормативные измерения.

## Читаемые подписи

По прямой просьбе пользователя текст чертежа отделён от масштаба геометрии. Название на экране остаётся не мельче 14 CSS px, площадь/количество — 12 px; при приближении кегль немного растёт. Длинное название занимает до двух строк, полная версия остаётся в title и доступном имени комнаты. Подпись получает светлую подложку и контрастную типографику Noto, сохраняющую казахские буквы.

`domain/plan-labels.mjs` пробует несколько свободных положений внутри доступной полосы помещения, затем близкие выноски. Видимые подписи не пересекаются, выноска не закрывает собственный якорь и центры соседних комнат. Выбранная комната обрабатывается первой. В тесном обзоре часть подписей скрывается с предложением приблизить план; доступные имена геометрии и поиск остаются полными. Центры за пределами видимой области не получают подпись на краю экрана. В редакторе верхние 32/44 px оставлены под служебную подпись и сетку.

`PlanLabels.tsx` измеряет текст загруженным Noto через Canvas, `usePlanViewport` следит за размером SVG. Обратное преобразование учитывает поля xMidYMid meet, поэтому шрифт не уменьшается при zoom/resize. Нажатие на выноску выбирает именно её комнату через data-plan-room; прежние pan/pinch и клавиатурный выбор сохраняются. В редакторе выноска позволяет выбрать/перенести свой блок; при других инструментах не перехватывает указатель.

SVG и PDF используют тот же алгоритм размещения с фиксированной поверхностью экспорта. В PDF название не мельче 9,3 pt, площадь — 8 pt. Полный перечень расчётных зон по-прежнему есть в отчёте; видимые подписи плана не являются перечнем оборудования или нормативным покрытием. Геометрия, площади и Snapshot от типографики не меняются.

Стили — `styles/plan-labels.css` после plan-workspace. Unit-проверки охватывают плотный план, приоритет выбора, перенос RU/KK, проекцию и неизменность данных. `scripts/labels-smoke.mjs` измеряет фактический кегль через getScreenCTM, пересечения/границы, tap по выноске, редактор и плотный обзор на 320 px.

Первичные ориентиры: [Mapbox: размещение подписей](https://docs.mapbox.com/help/dive-deeper/optimize-map-label-placement/) — проверка пересечений и несколько вариантов якоря; [MDN getScreenCTM](https://developer.mozilla.org/en-US/docs/Web/API/SVGGraphicsElement/getScreenCTM) — преобразование координат SVG. Это самостоятельная реализация для помещений, без зависимости от Mapbox.
