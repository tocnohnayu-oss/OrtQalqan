# Продукт и функции

Дата: 24.10.2026. Подтверждённые решения — в `DECISIONS.md`; статус реализации — в `HANDOFF.md`.

## Пользователь и задача

Инспектор ЧС вводит характеристики помещений, видит, какие огнетушители требуются в каждой зоне, уточняет исходные данные и получает воспроизводимый PDF. На объекте он работает с телефона, в кабинете — с компьютера.

Основной сценарий: **объект → этаж → помещение/расчётная зона → условия → расчёт → PDF**. Изменения зоны должны сразу отражаться на схеме; подтверждённый результат сохраняется отдельно от редактируемого черновика.

## Структура приложения

| Область | Назначение |
| --- | --- |
| Объекты | Переключать независимые черновики, создать объект из одной из шести структур, открыть учебный пример |
| Обход | Проверки помещения, наблюдения, реестр, сроки обслуживания, поиск и фильтры |
| Рабочее место | Выбрать этаж/зону, изменить параметры, посмотреть схему или план |
| Результат | Комплект ОП/ОУ, распределение по зонам, объяснение, незакрытые вопросы |
| Отчёт | Предпросмотр и PDF выбранной версии расчёта |
| Справка | Источники правил и понятные объяснения полей |

Для первого прототипа результат и справка открываются внутри рабочего места; полноценный административный кабинет не требуется.

## Разные объекты и обход

НИШ — один учебный пример. Сервис не ограничен образовательными зданиями. Библиотека хранит до 20 независимых объектов; шаблоны задают только названия помещений, а фактические характеристики вводит инспектор. Вид здания и область расчётной методики разделены. Для склада, производства и неизвестного назначения общественный профиль не применяется.

Параллельный сценарий: **объект → обход → помещение → проверки/оборудование → запись осмотра → следующее помещение → PDF/CSV**. На плане видно наличие записи и замечания. Число осмотренных помещений не означает процент пожарной безопасности.

Подробное поведение, поля и хранение описаны в `FIELD_WORKFLOW.md`.

## Поля ввода

| Уровень | Поле | Поведение |
| --- | --- | --- |
| Объект | Название, адрес | Идентификация в отчёте; адрес не влияет на количество |
| Объект | Назначение | Общественное, производственное, складское; задаёт область применимости правил |
| Объект | Инспектор и дата | Данные отчёта; без автоматически подставленных реальных людей |
| Этаж | Название/номер | Включая подвал, если он обследуется |
| Помещение | Название и площадь м² | Положительная площадь; не дублировать её одновременно в нескольких зонах |
| Помещение | Категория пожарной опасности | Если применима; выбирается по документации, а не по названию помещения |
| Помещение | Возможные классы пожара | Несколько классов; материал сопровождается краткой подсказкой |
| Условия | Электроника, оборудование под напряжением | Отдельно от обычной пожарной нагрузки; влияют на допустимость средств |
| Условия | Температурные условия | Нужны для пригодности модели; точные диапазоны — из паспорта оборудования |
| Условия | Автоматическое пожаротушение | «Есть / нет / не известно»; снижение количества требует подтверждённого применения правила |
| Условия | Особые материалы | Горючие металлы, реагенты и другие специальные случаи требуют отдельного подбора |
| Оборудование | Уже имеется, тип/характеристики | Необязательное сравнение с потребностью; простое число не подтверждает исправность |
| План | Изображение и точки установки | Ввод пользователя; без автоматического признания расстояний проверенными |

Поля раскрываются по контексту. Например, вопрос про уязвимую электронику нужен для соответствующего помещения; административные данные не должны загромождать расчёт.

## Графические режимы

**Схема** автоматически раскладывает помещения по этажам. Это навигация и обзор результатов. Схема всегда помечена «без масштаба».

**План** позволяет загрузить изображение своего этажа, поставить и удалить метки огнетушителей. Метки — предложения инспектора; загрузка изображения сама по себе не обеспечивает проверку маршрутов и расстояний.

Оба режима обращаются к одним зонам и одному результату; переключение не теряет данные. На телефоне схема открывается крупно, а параметры выбранной зоны — отдельным листом.

## Состояния расчёта

В «Сценариях» можно сравнить текущую зону с изменением площади, оборудования, условий, АУПТ или доступного комплекта. Сравнение не редактирует объект до отдельного применения. К зоне можно добавить замечание инспектора; запись сохраняется и входит в PDF. Поведение и исследование описаны в `RESEARCH_SCENARIOS.md`.

- Черновик: данные можно редактировать и сохранять.
- Недостаточно данных: указано, что именно нужно уточнить и где.
- Нужен специальный расчёт: случай за пределами проверенной области ядра.
- Рассчитано: количество получено по поддержанному набору правил.
- Результат устарел: исходные данные изменились после расчёта.

Отдельно показывать статус размещения: «не проверено» или результат отдельной проверки. Не объединять это с результатом количества в безусловный зелёный статус «всё соответствует».

## PDF

Первая страница: объект, дата, инспектор, тип документа, версия правил, сводный комплект ОП/ОУ, демонстрационный статус при необходимости, незакрытые вопросы.

Далее: исходные данные по зонам, таблица результатов, краткое обоснование со ссылками на пункты, схема/план и легенда при наличии, сведения о непроверенном размещении. При наличии полевых записей — приложение с ответами, состоянием оборудования и введёнными сроками. Строки не обрезаются; таблица продолжается на следующих страницах.

Отчёт содержит читаемый текст, а не снимок экрана. Язык выбирается перед экспортом. Он фиксирует конкретный результат и не меняется задним числом при редактировании объекта.

## Граница первой версии

Полезное ядро: ввод объекта, этажи и зоны, графика, поддержанный расчёт ОП/ОУ, сохранение черновика на устройстве, два языка, PDF. История проведённого обслуживания с документами, сканирование QR, распознавание планов, ЭЦП, роли, облачная синхронизация и интеграции с государственными системами — дальнейшие этапы.

Производственное качество интерфейса означает рабочие состояния, доступность и понятные действия. Полноценный ведомственный запуск дополнительно потребует проверенного нормативного набора, управления доступом и согласования хранения данных.
