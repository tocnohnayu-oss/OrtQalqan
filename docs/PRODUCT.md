# Продукт и функции

Обновлено: 29.10.2026. Подтверждённые решения — в `DECISIONS.md`; статус реализации — в `HANDOFF.md`.

## Пользователь и задача

Инспектор ЧС вводит характеристики помещений, видит, какие огнетушители требуются в каждой зоне, уточняет исходные данные и получает воспроизводимый PDF. На объекте он работает с телефона, в кабинете — с компьютера.

Основной сценарий: **объект → атлас здания → этаж → помещение/расчётная зона → условия → расчёт → PDF**. Изменения зоны должны сразу отражаться на схеме; подтверждённый результат сохраняется отдельно от редактируемого черновика.

## Структура приложения

| Область | Назначение |
| --- | --- |
| Здание · атлас | Цельная 3D-модель/разрез, каталог с настоящими миниатюрами этажей, выбор комнаты и исходные записи; возврат сохраняет ракурс текущего сеанса на телефоне и ПК |
| Объекты | Переключать независимые черновики, создать объект из одной из шести структур, открыть учебный пример |
| Обход | Проверки помещения, наблюдения, реестр, сроки обслуживания, поиск и фильтры |
| Лист внимания внутри обхода | Наблюдения и сроки по объекту или выбранной комнате, точная исходная запись, возврат к контуру в 3D либо метке изображения; CSV всего объекта и PDF снимка |
| Рабочее место | Выбрать этаж/зону, изменить параметры, посмотреть схему или план |
| Результат | Комплект ОП/ОУ, распределение по зонам, объяснение, незакрытые вопросы |
| Отчёт | Предпросмотр и PDF выбранной версии расчёта |
| Справка | Источники правил и понятные объяснения полей |

Для первого прототипа результат и справка открываются внутри рабочего места; полноценный административный кабинет не требуется.

## Разные объекты и обход

НИШ — один учебный пример. Сервис не ограничен образовательными зданиями. Библиотека хранит до 20 независимых объектов; шаблоны задают только названия помещений, а фактические характеристики вводит инспектор. Вид здания и область расчётной методики разделены. Для склада, производства и неизвестного назначения общественный профиль не применяется.

Параллельный сценарий: **объект → обход → помещение → проверки/оборудование → запись осмотра → следующее помещение → PDF/CSV**. На плане видно наличие записи и замечания. Число осмотренных помещений не означает процент пожарной безопасности.

Подробное поведение, поля и хранение описаны в `FIELD_WORKFLOW.md`.

## Поля ввода

| Уровень | Поле | Поведение |
| --- | --- | --- |
| Объект | Название, адрес | Идентификация в отчёте; адрес не влияет на количество |
| Объект | Назначение | Общественное, производственное, складское; задаёт область применимости правил |
| Объект | Инспектор и дата | Данные отчёта; без автоматически подставленных реальных людей |
| Этаж | Название/номер | Включая подвал, если он обследуется |
| Помещение | Название и площадь м² | Положительная площадь; не дублировать её одновременно в нескольких зонах |
| Помещение | Категория пожарной опасности | Если применима; выбирается по документации, а не по названию помещения |
| Помещение | Возможные классы пожара | Несколько классов; материал сопровождается краткой подсказкой |
| Условия | Электроника, оборудование под напряжением | Отдельно от обычной пожарной нагрузки; влияют на допустимость средств |
| Условия | Температурные условия | Нужны для пригодности модели; точные диапазоны — из паспорта оборудования |
| Условия | Автоматическое пожаротушение | «Есть / нет / не известно»; снижение количества требует подтверждённого применения правила |
| Условия | Особые материалы | Горючие металлы, реагенты и другие специальные случаи требуют отдельного подбора |
| Оборудование | Уже имеется, тип/характеристики | Необязательное сравнение с потребностью; простое число не подтверждает исправность |
| План | Изображение и точки установки | Ввод пользователя; без автоматического признания расстояний проверенными |

Поля раскрываются по контексту. Например, вопрос про уязвимую электронику нужен для соответствующего помещения; административные данные не должны загромождать расчёт.

## План и конструктор

Основной экран упрощён: объект, этажи, план, выбранное помещение. Расчёт и PDF — в шапке; история, сценарии и справка — в «Ещё». Панель параметров появляется после выбора зоны. Нет плавающего итога, отдельной полосы прогресса или придуманного автоматически корпуса.

План начинается пустым. **Готовые блоки** подбираются по виду здания. Школьный набор включает классы, библиотеку, лабораторию, спортзал и общие пространства. Блок перетаскивается на этаж, меняет размер числом или угловыми точками; условная обстановка подстраивается автоматически. Совмещение с коридором создаёт дверь на общей стене.

Ручной ортогональный контур остаётся для нестандартной формы. Можно редактировать дверь/окно, отменять действия, скачивать SVG. Редактор работает с временным черновиком, применяется отдельным сохранением. Удаление формы не удаляет расчётную зону. Площади переносятся в расчёт по отдельному выбору, а новые пожарные характеристики не придумываются.

**Изображение** позволяет загрузить готовый план этажа и поставить метки ОП/ОУ. Автоматического распознавания или проверки маршрутов нет. Изображение и построенный план могут храниться одновременно.

См. `FLOOR_EDITOR.md` для модели данных, готовых наборов и поведения редактора.

## Состояния расчёта

В «Сценариях» можно сравнить текущую зону с изменением площади, оборудования, условий, АУПТ или доступного комплекта. Сравнение не редактирует объект до отдельного применения. К зоне можно добавить замечание инспектора; запись сохраняется и входит в PDF. Поведение и исследование описаны в `RESEARCH_SCENARIOS.md`.

- Черновик: данные можно редактировать и сохранять.
- Недостаточно данных: указано, что именно нужно уточнить и где.
- Нужен специальный расчёт: случай за пределами проверенной области ядра.
- Рассчитано: количество получено по поддержанному набору правил.
- Результат устарел: исходные данные изменились после расчёта.

Отдельно показывать статус размещения: «не проверено» или результат отдельной проверки. Не объединять это с результатом количества в безусловный зелёный статус «всё соответствует».

## PDF

Первая страница: объект, дата, инспектор, тип документа, версия правил, сводный комплект ОП/ОУ, демонстрационный статус при необходимости, незакрытые вопросы.

Далее: исходные данные по зонам, таблица результатов, краткое обоснование со ссылками на пункты, схема/план и легенда при наличии, сведения о непроверенном размещении. При наличии полевых записей — приложение с ответами, состоянием оборудования и введёнными сроками. Строки не обрезаются; таблица продолжается на следующих страницах.

Отчёт содержит читаемый текст, а не снимок экрана. Язык выбирается перед экспортом. Он фиксирует конкретный результат и не меняется задним числом при редактировании объекта.

## Граница первой версии

Полезное ядро: ввод объекта, этажи и зоны, графика, поддержанный расчёт ОП/ОУ, сохранение черновика на устройстве, два языка, PDF. Добавлены собственные аккаунты и серверная база групп с ответственными, ролями и журналом; см. `ACCOUNTS.md`. Общий сервер ещё не размещён. История обслуживания с документами, сканирование QR, распознавание планов, ЭЦП и интеграции с государственными системами — дальнейшие этапы.

Производственное качество интерфейса означает рабочие состояния, доступность и понятные действия. Полноценный ведомственный запуск дополнительно потребует проверенного нормативного набора, управления доступом и согласования хранения данных.

## Первое знакомство и демонстрация результата

В шапке есть повторно запускаемая инструкция. Первое посещение предлагает короткий экскурc, который можно отложить. Подписанный вход и имя пользователя заменяют отдельную квадратную иконку аккаунта. Учебный пример открывается отдельной копией по явному действию, без регистрации и без изменения объектов группы.

Явный расчёт открывает результат с исходной площадью, действующим в профиле коэффициентом, округлением и количеством для каждой зоны; неподдержанные зоны требуют отдельного подбора. После этого доступен PDF из того же снимка. Это делает основную задачу видимой на защите и в обычной работе; статус предварительного профиля не скрывается. Сценарий четырёхминутного показа — `DELIVERY.md`, нерешённые риски — `JURY_REVIEW.md`.

## Найти и продолжить работу

На плане доступен поиск по помещениям на всех этажах текущего объекта и по номерам/моделям реестра. Совпадение комнаты открывает её параметры; совпадение оборудования — существующую запись в обходе без редактирования. Без чертежа доступен ввод параметров, но форма не создаётся автоматически.

В каждой строке глобального поиска есть отдельное расположение: настоящий контур в 3D при вызове из здания или существующий 2D источник. Изображение на смешанном этаже не заменяется чужим контуром. Слой и сцена модели сохраняются. Выдача растёт по 40, одинаковые номера не скрывают последующие записи. Все условия об оборудовании должны совпасть у одного Asset вместе с контекстом комнаты/этажа. Запрос не сохраняется в объект/аккаунт.

Обход из шапки продолжает незавершённые ответы на дату, а из параметров комнаты — выбранное помещение. Переход к следующему учитывает поисковый запрос и фильтр списка.

Названия помещений на чертеже сохраняют читаемый экранный размер при уменьшении этажа. Перенос и выноски помогают узким помещениям; тесный обзор предлагает приблизить план. Нажатие на подпись открывает её комнату. Это представление введённых данных, которое не меняет геометрию, расчётную площадь или нормативную методику.

## Завершение обхода и достоверность состояния · 28.10.2026

Открытая форма различает черновик, готовые ответы и записанный осмотр на Building.date. Отметка другой даты видна отдельно и не переносится автоматически. Фильтр внимания включает текстовые наблюдения и пробелы даты обслуживания, с отдельной пометкой уточнения. Завершённое помещение с наблюдением остаётся доступным для проверки. Исправление причины сохраняет открытую форму и поясняет её выход из выборки; фокус после изменения реестра возвращается к записи. Для неизвестного расположения нет ложного перехода к карте. Реализация не меняет расчёт, API/SQLite, историю или серверное сохранение; контракт — INSPECTION_REVIEW.md.

## Сверка перед новым результатом · 29.10.2026

После правки действие «Что изменилось» сопоставляет последний результат текущего сеанса и текущий черновик. План и парные значения показывают причину изменения комплекта; поля объекта, геометрия, осмотр, заметки и точные записи оборудования доступны без поиска в сыром JSON. Можно перейти к актуальным параметрам, посмотреть исходное обоснование или явно обновить расчёт. PDF остаётся связан со Snapshot и блокируется при stale. Просмотр не меняет исходные данные, не создаёт долговременную историю и не подтверждает нормативную методику. Технический контракт — CHANGE_REVIEW.md.

## Уточнение представления · 29.10.2026

По запросу на более простой дизайн сверка показывает один переключаемый план и видимые парные значения. Индекс изменений раскрывается по выбранному имени, расчётные и полевые данные остаются в одном листе. Рабочая шапка упрощена, этажи оформлены светлым каталогом. Изменение не меняет области расчёта, источники, схему Building/SQLite, историю сеанса или защиту PDF. Текущий контракт — UI_SIMPLIFY.md.

## Последний визуальный слой · минимализм

Уточнение пользователя реализовано как единый спокойный рабочий интерфейс: меньше декоративных блоков и повторных метаданных, белые поверхности, компактный каталог и простые состояния контролов. Сохраняются один переключаемый источник сравнения, реальные миниатюры/планы/3D, данные, предупреждения, собственные аккаунты и PDF. Геометрия/расчёт/API не менялись; детали — MINIMAL_UI.md.
