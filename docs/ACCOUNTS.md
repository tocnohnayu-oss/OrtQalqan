# Собственные аккаунты и общая база

24.10.2026. Пользователь явно выбрал **собственные аккаунты**, почта/пароль. Это отдельный Node.js сервер с SQLite, без зависимости от входа ChatGPT. В текущем Sites ещё нет опубликованной версии; статический хостинг не запускает этот Node backend. Рабочий общий адрес появится после размещения сервера с постоянным диском и HTTPS.

## Модель работы

Новый аккаунт создаёт собственную рабочую группу и становится её координатором. Человек может участвовать в нескольких группах; переключатель показывает только доступные ему. Для вступления в существующую группу нужен одноразовый токен приглашения. Ссылку вручную передаёт координатор; автоматических писем нет.

| Сущность | Содержание |
| --- | --- |
| users | UUID, имя, нормализованная почта, хеш пароля |
| workspaces / memberships | Группы и членство; coordinator / inspector |
| sessions | Хеш случайного токена и абсолютный срок 12 часов |
| objects | JSON существующего Building, группа, ответственный, этап, версия, автор/время изменения |
| invitations | Хеш одноразового токена, срок 7 дней, использование/отзыв |
| events | Автор, действие, объект, время; последние 50 событий доступны в UI |

Все участники редактируют объекты своей группы. Только координатор назначает ответственного, меняет этап и создаёт/отзывает приглашения. Ответственный — рабочее назначение, не единственный человек с доступом. Этапы «Подготовка / Обход / На проверке / В архиве» не означают пожарную безопасность или нормативное заключение. Удаления объектов/участников и передачи роли координатора пока нет; архив — этап записи.

## Интерфейс

Верхний значок открывает вход или рабочее пространство. Оно оформлено как папка атласа: типографический разворот, собственная иллюстрация личного паспорта/плана, индексированные вкладки «Объекты / Участники / Журнал», линейные строки с архитектурными миниатюрами. На телефоне диалог занимает весь экран. Не возвращать округлённые карточки, декоративные метрики и вымышленную онлайн-активность.

В объектах есть поиск, «Все / Назначено мне / Без ответственного», ответственный, этап и реальное время последнего сохранения. Изменение назначения находится в раскрывающейся форме. В участниках — имена, роли и приглашения. В журнале — реальные серверные события. Приватный токен приглашения показывается только создателю при генерации, не возвращается в списках.

## Сохранение и конфликт

Общий объект сохраняется явной кнопкой **«Сохранить в базу»**. Изменения в открытом плане/обходе остаются на экране до этого действия. Выход/смена объекта предупреждает о несохранённом содержимом; браузер также предупреждает перед закрытием страницы. Это не автоматическая синхронизация и не совместное редактирование в реальном времени.

`objects.version` — серверная версия, независимая от `Building.revision`. Сохранение данных и изменение назначения передают ожидаемую серверную версию. В одной транзакции проверяется текущая версия, записывается новое содержимое и событие. Устаревший запрос получает HTTP 409. UI оставляет черновик на экране и предлагает скачать свою копию JSON или явно загрузить версию базы. Автоматического слияния геометрии нет.

Открытие объекта группы не записывает его в localStorage. Перед этим в памяти сохраняется локальная библиотека; выход возвращает её. Снимки/история текущей сессии очищаются при переходе между локальным и общим объектом. Смена аккаунта после истечения сессии не должна показывать объект предыдущего пользователя. Язык интерфейса остаётся предпочтением устройства. Резервный JSON — явное отдельное действие.

## Запуск

Node.js **24.14+**, зависимости фронтенда установлены обычным `npm install`.

```sh
npm run dev
```

Команда запускает API на 127.0.0.1:8787 и Vite на 127.0.0.1:5173. `/api` проксируется в сервер; Vite запрещает отдачу var/, SQLite и env-файлов. При обновлении с предыдущей версии нужно перезапустить старый процесс Vite, чтобы запустился и API.

```sh
npm run build
ORTQALQAN_ORIGIN=http://127.0.0.1:8787 npm start
```

Собранный Node сервер отдаёт dist/ и API с одного origin. `.env.example` перечисляет параметры; `npm run dev` и `npm start` читают локальный `.env`, если он есть. Для размещения задать точный внешний HTTPS origin, интерфейс/порт и постоянный путь `ORTQALQAN_DATABASE`. По умолчанию база — `var/ortqalqan.sqlite`. Не использовать эфемерный диск или статический deploy для общих данных. Несколько Node процессов/распределённый кластер этим прототипом не предусмотрены.

## API

| Метод / путь | Действие |
| --- | --- |
| GET /api/session | Текущий пользователь и доступные группы |
| POST /api/auth/register, /login, /logout | Регистрация, вход, отзыв сессии |
| GET /api/workspaces/:wid | Участники, сводки объектов, журнал, активные приглашения координатора |
| POST /api/workspaces/:wid/objects | Создание из шаблона/явной копии локального черновика |
| GET /api/workspaces/:wid/objects/:id | Объект целиком |
| PUT /api/workspaces/:wid/objects/:id | Содержимое + ожидаемая версия |
| PATCH /api/workspaces/:wid/objects/:id | Ответственный/этап + ожидаемая версия; coordinator |
| POST /api/workspaces/:wid/invitations | Одноразовое приглашение; coordinator |
| DELETE /api/workspaces/:wid/invitations/:id | Отзыв приглашения; coordinator |
| POST /api/invitations/accept | Вступление авторизованного пользователя по токену |

Сервер проверяет членство при каждом запросе, а не доверяет workspaceId в браузере. Чужой объект через доступную группу тоже недоступен. Тела JSON до 6 МБ; существующий Building проходит общую валидацию плюс ограничения длины заголовков. Ограничения: 200 объектов/100 участников/10 активных приглашений на группу. Изображения пока хранятся внутри JSON объекта; отдельного файлового хранилища нет.

## Устройство хранения и аутентификации

- `server/application.mjs` — API и транзакции. `server/index.mjs` — HTTP/статическая раздача только dist/.
- `server/migrations/001-workspaces.sql` — схема; применяется один раз с user_version=1. Следующие изменения требуют новой миграции, не редактирования уже развёрнутой 001.
- Пароли: scrypt N=2^17, r=8, p=1, случайная соль; пароль не хранится и не возвращается. Подбор хеша ограничен двумя одновременными операциями. Есть ограничение попыток по адресу соединения и хешу почты. Оно действует в памяти одного процесса.
- Случайные сессии и приглашения хранятся в базе только как SHA-256 хеши. Cookie HttpOnly, SameSite=Strict; Secure автоматически при HTTPS origin. Мутирующие запросы принимают JSON и требуют точного Origin; CORS не открывается. Ответы API no-store.
- Ссылка приглашения использует fragment `#join=...`, который не передаётся HTTP серверу. После чтения fragment убирается из адресной строки. Приглашение даёт доступ его получателю; отправитель сам выбирает адресата.
- var/, *.sqlite*, .env и результаты QA игнорируются Git. База содержит приватные сведения и сессии; не помещать её в public/, dist/, артефакты или публичный репозиторий. CI использует временную синтетическую базу вне checkout и удаляет её. Бэкап рабочей SQLite делать штатным SQLite backup/после остановки сервера; одного файла при активном WAL недостаточно.

Первичные технические источники: [Node.js SQLite](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html), [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html), [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html). Это обоснование конкретных механизмов, а не утверждение о сертификации системы.

## Границы прототипа

Общий сервер ещё не размещён. Подтверждения почты, восстановления/смены пароля, MFA, почтовой доставки, политики резервирования, административного удаления аккаунта и независимого аудита безопасности нет. Почта — идентификатор входа; владение адресом не проверяется. Членство в чужой группе требует приглашения. Для реального ведомственного пилота эти вопросы и условия размещения персональных данных нужно решить отдельно.
