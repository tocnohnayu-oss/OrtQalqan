# Дизайн и пользовательский опыт

## Направление

Полевой атлас с профессиональной светлой айдентикой. Бумажный фон, чернильная типографика, терракотовый акцент, собственный знак защиты и архитектурные SVG-иллюстрации. В центре — план, построенный пользователем из готовых блоков с узнаваемой обстановкой. До ввода геометрии показывается пустой лист. Актуальная система описана в `BRAND.md`.

Переработка 28.10.2026 делает графику первым рабочим инструментом: уменьшенная шапка освобождает место модели, каталог показывает настоящие контуры этажей, вкладки разделяют слои, инструменты камеры объединены по назначению. Название объекта, источник сохранения и явная смена объекта остаются видимыми. Над моделью больше нет отдельной повторной строки «3D-модель здания»; дата перенесена к слоям. Общий маршрут и нативные листы не меняются.

Проверяется не только картинка: на 1440×1050 камера и открытие этажа должны помещаться до прокрутки, миниатюры — соответствовать Floor.layout/plan, на 320 px KK — сохраняться полное имя/фокус исходной комнаты и цели навигации от 44 px. Для длинных названий допустима высота по содержимому, горизонтальная прокрутка страницы недопустима. Подготовка — `DESIGN_REWORK.md`.

## Компоновка компьютера

```text
┌──────────────────────────────────────────────────────────────┐
│ OrtQalqan       План / Обход / Ещё                 RU / ҚАЗ │
│ Объекты / Название объекта                  Расчёт / PDF    │
├──────────────┬─────────────────────────────┬─────────────────┤
│ Этажи        │ Схема / План                │ Выбранная зона  │
│ 01           │                             │ Название        │
│ 02           │     Помещения с обстановкой │ Площадь         │
│ 03           │                             │ Условия         │
│ + этаж       │                             │ Обоснование     │
│              │                             │ (после выбора)  │
└──────────────────────────────────────────────────────────────┘
```

На телефоне этажи становятся горизонтальными вкладками. Параметры выбранной зоны открываются в выдвижном листе. Основное действие закреплено внутри редактора и обхода, на главном экране постоянной нижней панели нет. Перетаскивание имеет альтернативу обычными кнопками.

## Визуальная система

| Элемент | Решение |
| --- | --- |
| Фон | Тёплая белая бумага; чертёж на лёгкой координатной сетке |
| Текст | Тёмный графит, спокойный серый для второстепенных подписей |
| Акцент | Сдержанная терракота для знака, выбранной зоны и главного действия |
| ОП / ОУ | Различимые обозначения, иконка + короткий текст; цвет служит дополнительным признаком |
| Ошибка / уточнение | Красный / янтарный, обязательная текстовая причина |
| Шрифт | Noto Sans с полноценными казахскими символами, локальные файлы |
| Размеры | Основной текст 14–16 px; крупные числовые итоги; умеренные заголовки |
| Формы | Подпись над полем, единица измерения внутри/рядом; ошибки у своего поля |
| Иконки | Один набор Lucide; подписи для основных действий |
| Движение | Короткие переходы; учитывать reduced motion |

Не полагаться на hover, цвет, мелкий tooltip или иконку без доступного имени. Небольшая поясняющая фраза полезнее непонятного символа.

## Что показывает графика

Схема показывает реальные сущности данных: этажи, помещения, выбранную зону, класс/условия, необходимый комплект. Нажатие на помещение открывает его параметры и основание результата. Итог по этажу виден без открытия каждой зоны.

После пересмотра на плане нарисованы стены, двери с дугами открывания, окна, коридор, вход, лестница и обстановка помещений. Масштаб управляется кнопками; изменения площади влияют на расчёт, но не сдвигают стены. Это остаётся иллюстративной композицией. На телефоне контекстная форма открывается в нижнем листе; расчёт и PDF доступны из постоянной панели действий.

Условные блоки не изображают подтверждённую архитектуру школы. На неподтверждённой схеме нельзя рисовать окружности «зоны покрытия», вычислять расстояния по пикселям или обещать оптимальное размещение.

В режиме плана изображение пользователя остаётся подложкой. Метка огнетушителя выбирается нажатием, получает тип, связанный этаж и зону; её можно убрать. До появления масштаба, препятствий и проверенного алгоритма измерений размещение остаётся непроверенным.

## Результаты и детали

Верхний уровень отвечает на три вопроса: какой комплект нужен, в каких зонах есть вопросы, можно ли выгрузить актуальный результат. Подробности формулы и источника раскрываются по действию «Почему столько?».

Сравнение имеющегося оборудования с требуемым — горизонтальные полосы или простая пара чисел. Статистика по времени, произвольные индексы риска и графики без исходных данных не нужны.

## Языки и доступность

Единый переключатель RU / ҚАЗ работает без потери ввода. Обе версии включают состояния формы, подписи SVG, единицы, сообщения сохранения, справку и PDF. Машинный перевод нормативных терминов требует проверки человеком, владеющим казахским.

Для основных touch-действий целевой размер — 44 px и более. Это продуктовый ориентир; минимум WCAG 2.2 AA для соответствующего критерия имеет исключения и не равен универсальному требованию 44 px. Источник: [W3C, Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).

Текстовые альтернативы схемы, клавиатурный выбор зон, контраст, видимый фокус и корректные заголовки обязательны. [Radix](https://www.radix-ui.com/primitives/docs/overview/accessibility) помогает с фокусом и клавиатурными шаблонами, но доступность приложения проверяется целиком.

## Библиотека и обход — 24.10.2026

Пользователь уточнил: продукт для разных зданий, НИШ не должна определять весь интерфейс. Библиотека оформлена как индекс атласа; типология объекта выбирает собственный архитектурный эскиз. Рисунки не претендуют на сходство с реальным зданием. Для фактического плана служит загрузка изображения.

Обход открывается из верхней навигации. В журнале слева список помещений и фильтры, справа один осмотр с контекстной сценой. Число осмотренных помещений обозначает записи, не безопасность. На телефоне список изначально свёрнут и раскрывается по действию; поля и ответы остаются подписанными.

Добавление оборудования раскрывает одну форму. При уходе из несохранённой формы требуется подтверждение. Состояние «не проверено» явно отличается от ответа «проверено»; замечание не снимается после завершения записи осмотра.

## Пересмотр по обратной связи: конструктор блоков

24.10.2026 пользователь попросил уменьшить сложность и заменить нереалистичный автоматический корпус готовыми блоками помещений. Главный экран теперь состоит из компактной шапки объекта, списка этажей/зон и плана. Параметры скрыты до выбора. Иллюстрация корпуса, метрики, прогресс и плавающий итог убраны с основного экрана. Второстепенные действия находятся в «Ещё».

Основной способ конструктора — тематический набор готовых помещений с миниатюрами обстановки. Перетаскивание/изменение размера сохраняет парты, доску, стеллажи и другие символы. Есть кнопочная/клавиатурная альтернатива перетаскиванию. Ручные стены/контуры остаются дополнительным способом. На телефоне набор горизонтальный, параметры прокручиваются отдельно, действия сохранения остаются внизу редактора.

Пустой план — осознанное состояние. Имеющиеся расчётные зоны доступны списком, но не выдаются за фактическую архитектуру здания.

## Характер без усложнения

Последний пересмотр заменяет округлённые контейнеры листами и индексами технического атласа. Крупный узкий заголовок помогает быстро узнать объект; этажи читаются по номеру, готовые комнаты — по обстановке и названию. Срез заливки основной кнопки повторяется в метке заголовка диалога. Список действий, геометрия конструктора и порядок обхода остаются прежними. На телефоне сохраняются доступные ответы в одну строку, закреплённое действие обхода и горизонтальный каталог блоков. См. актуальные токены и ограничения в `BRAND.md`.

## Личное пространство и архив группы

По выбору пользователя вход выполняется собственной почтой/паролем. Отдельный разворот объединяет типографическую обложку атласа и компактную форму; самостоятельная SVG показывает папку плана и рабочий паспорт. Авторизованный экран использует индексированные вкладки «Объекты / Участники / Журнал». Строка объекта показывает ответственного, этап и последнее серверное сохранение. Назначение раскрывается по действию, поиск и фильтр «Назначено мне» остаются рядом со списком. На узком экране архив и вход полноэкранные.

В основном плане добавлена только короткая строка группы/ответственного и кнопка сохранения. Общий объект сохраняется явно. Конфликт версий оставляет изменения на экране и предлагает скачать свою копию либо загрузить серверную. На входе локальный черновик не отправляется автоматически: пользователь сам выбирает копирование в группу. Выход возвращает прежнюю библиотеку устройства. Подробности реализации и ограничений — `ACCOUNTS.md`.

## Явная смена объекта

Пользователь не заметил маленькую ссылку «Объекты ›». Над названием открытого объекта теперь отдельная контрастная кнопка «Сменить объект» / «Нысанды ауыстыру» с иконкой переключения и высотой не менее 44 px. Она открывает сохранённые объекты в гостевом режиме или архив рабочей группы после входа. Название активного здания и редактирование его данных остаются отдельными действиями. Кнопка доступна с клавиатуры и на телефоне; смена общего объекта сохраняет существующую защиту несохранённых правок.

## Инструкция и видимый результат

Квадратная иконка аккаунта заменена подписанным входом; авторизованного пользователя видно по имени. Первый запуск предлагает пять коротких подсказок с подсветкой реальных действий. Инструкция доступна повторно из шапки и позволяет открыть готовый учебный объект без регистрации. Подсказки ничего не меняют в данных; пример создаётся отдельным явным действием.

Кнопка расчёта теперь открывает результат, а не только меняет маленький счётчик. На листе результата — реальные количества ОП/ОУ, формула и округление каждой поддержанной зоны, разница с вручную указанным наличием, ручные случаи, источники и переход к PDF. Все числа берутся из Snapshot. Нет постоянной новой панели на основном плане. Отдельный учебный пример и сценарий показа описаны в `JURY_REVIEW.md`; это не фактическая архитектура школы и не завершённая нормативная экспертиза.

## Осмотр плана и исправление результата

План перемещается мышью или одним пальцем, масштабируется двумя пальцами, кнопками либо Ctrl/Cmd + колесо. Клавиатура: стрелки, +/−, 0/Home. Нажатие на комнату открывает параметры; завершение перетаскивания/масштабирования комнату не выбирает. Есть отдельное приближение выбранного помещения и возврат ко всему этажу. На телефоне новое выбранное помещение автоматически приближается, чтобы небольшую комнату можно было прочитать после закрытия параметров. На компьютере выбранная извне комната возвращается в кадр, если её центр оказался за границей текущего вида.

Переключатель ОП/ОУ находится под планом и доступен на телефоне. Он показывает количества из актуального снимка; для неподдержанных зон явно нужен подбор. При правках прежние количества скрываются с предложением обновить расчёт. Это подписи количества, а не физические точки установки.

На листе результата у каждого помещения есть «Изменить». Действие открывает текущий этаж и параметры нужной зоны с фокусом на площади; на телефоне — лист параметров. Для устаревшего снимка переход заблокирован до обновления.

## Поиск и продолжение обхода

Поиск встроен в список помещений: название RU/KK, этаж, номер или модель оборудования. Ищет только в открытом объекте. Результаты сгруппированы по этажам; одинаковые названия и номера не сливаются. Для больших списков сначала 30 помещений, затем явное «Показать ещё»; прокрутка списка не растягивает план. Пустой запрос возвращает комнаты текущего этажа. Escape очищает запрос с сохранением фокуса.

Совпадение комнаты открывает её этаж и параметры. Зоны без формы доступны, но не получают вымышленного контура. Совпадение оборудования открывает обход с раскрытым реестром, подсвечивает запись и переводит фокус на неё без редактирования. Этаж и помещение остаются над найденным номером, даже когда заголовок прокручен. Закрытие возвращает фокус в поиск, переход на план — к самому плану. Возврат на план сохраняет выбранный этаж/комнату. Запрос не записывается в историю или локальное хранилище.

«Обход» в шапке продолжает начатые ответы, затем первое ещё не осмотренное помещение на дату; кнопка в параметрах комнаты открывает именно её. Следующая комната учитывает поиск и фильтр. Для фильтра внимания доступны и завершённые записи с замечаниями; в конце списка переход останавливается. Никакой оптимальный маршрут или итог соответствия не строится.

## Узнаваемость без новой панели

Визуальная шапка объединяет тип здания и его название с собственной архитектурной иллюстрацией. Смена объекта остаётся явной кнопкой. Контрастный выбранный этаж и порядковый индекс листа помогают удерживать контекст. Поиск, построение и расчёт остаются на прежних местах.

Пустой план получил тематический рисунок готовых блоков и короткое действие «Начните с первого помещения». На широком экране текст стоит рядом с рисунком; на телефоне они складываются в колонку. Это не подложка реального плана. Тот же рисунок обстановки используется конструктором, SVG и PDF. Лист расчёта и индексы обхода продолжают оформление атласа.

## Рабочий лист на весь экран

План разворачивается отдельным действием; имя объекта, этажи и выход остаются перед глазами. Камера и черновик сохраняются. На телефоне поиск комнат раскрывается по необходимости, освобождая место чертежу. Выход возвращает в прежнее место страницы. Окна редактирования работают поверх листа с прежними подтверждениями несохранённых изменений.

Каталог конструктора получил более крупные миниатюры и связь с типом выбранной комнаты. Поворот теперь доступен у чертежа, рядом с масштабом; имя и текущий угол показаны там же. Это повторяет строгий характер атласа и сокращает прокрутку свойств.

## Типографика чертежа

Названия и площади сохраняют читаемый размер независимо от масштаба этажа. Длинные имена переносятся, узкие комнаты получают близкую выноску с линией привязки. Нажатие на неё открывает её комнату. Выбранная подпись имеет приоритет и терракотовую рамку; обычные — спокойную светлую подложку. Соседние подписи не накладываются друг на друга. На плотном плане появляется предложение приблизить, а не ещё более мелкий текст. Просмотр, конструктор и экспорт используют один принцип размещения.

## Лист выбранного помещения

Параметры сохраняют пространственный контекст: название этажа, полное имя комнаты и небольшая миниатюра её фактического введённого контура/обстановки. Без формы миниатюра не создаётся. Если есть только метка на изображении, доступен возврат к этой метке. «Показать на плане» возвращает фокус к чертежу и явно приближает выбранную комнату, даже после ручного перемещения камеры.

Стрелки переключают комнаты текущего этажа в порядке списка, останавливаясь на границах. Лист остаётся открытым, заголовок получает фокус, прокрутка возвращается к началу, дополнительные разделы сворачиваются. Это навигация по данным, не маршрут обхода и не отметка осмотра.

Рядом с полем площади видна площадь введённого контура. При различии показаны знак ≠ и короткое объяснение, что расчёт использует введённое значение. Синхронизации по нажатию на подсказку нет; прежний явный перенос площадей в редакторе сохраняется.

Результат комнаты оформлен графикой выбранного типа и крупным количеством. Поле наличия доступно здесь же, без раскрытия «Деталей». После редактирования прежние числа скрываются; «Обновить результат» пересчитывает объект, сохраняя открытое помещение. «Обоснование расчёта» открывает прежний лист Snapshot. Реестр не подменяет ручное наличие.

## Графический каталог

На широком экране этажи и индекс комнат объединены чернильной поверхностью; выбранный этаж — светлая вкладка. План, параметры и основные действия остаются светлыми. Цветовой контраст отделяет навигацию от чертежа. Рядом с названием комнаты стоит собственный предметный символ явно выбранного блока; полное имя сохраняется текстом. Поиск оборудования продолжает использовать метку реестра.

На телефоне светлая строка этажей и комнат экономит место; выбранная комната подчёркнута. Крупные читаемые подписи на самом плане, раскрытие поиска в развёрнутом режиме и прежние touch-жесты сохраняются. Символы не назначают класс пожара и не создают отсутствующую геометрию.

Панель плана на телефоне состоит из двух строк: полное название этажа/переключение вида и ряд действий. Все видимые инструменты имеют область нажатия от 44 px, экспорт SVG не зависит от языка подписи. Клавиатурный фокус сохраняет контраст и на тёмном каталоге, и на светлой выбранной вкладке.

## От обхода к конкретным действиям

В верхней строке обхода есть подписанный «Лист внимания» со счётчиком записей. Он собирает наблюдения, состояния и даты по всему объекту без дополнительной панели на плане. Крупный заголовок, оригинальная графика листа/календаря и четыре нумерованных раздела продолжают атлас. Записи — строки с этажом, полным названием, причинами, источником и двумя явными действиями. Непроверенное состояние и отсутствующая дата стоят в разделе уточнения, не выдаются за нарушение.

Поиск и выбор раздела остаются при открытии исходной записи. Возврат приводит к прежней строке с фокусом. Исправление выполняется в существующей форме, а выборка сразу обновляется. Список ограничен 40 строками с продолжением. Для помещения без геометрии нет вымышленной ссылки на форму плана. Выгрузка подписана как весь объект, даже если текущий экран отфильтрован. Пустой лист не сообщает, что объект безопасен.

Визуальное ревью на 320 px выявило слишком длинное вступление. Мобильный лист получил короткий предметный заголовок без вводного абзаца и более крупный текст причин/наблюдений; реальные записи начинаются раньше. В верхней строке остаются выгрузка текущего вида и PDF с целями 44 px.

## Здание · цельная 3D-модель

Пользователь отверг раскладку листов. Обзор заменён цельной моделью на Three.js: реальные контуры формируют стены/перекрытия/кровлю, проёмы — стекло/двери. Мышь и один палец вращают, колесо и два пальца масштабируют. Разрез убирает верхние этажи и открывает комнаты выбранного; пустые/только изображения не достраиваются автоматически. Условная высота видна и меняется отдельно от данных объекта.

Чернильный каталог и строгая типографика сохраняют айдентику, а центр занимает настоящая интерактивная сцена с освещением/тенями. Телефон использует ту же модель и органы управления 44 px. Цвет осмотра/расчёта и текстовая легенда помогают читать данные без утверждения соответствия. Быстрый поиск Ctrl/⌘ K ведёт к точному источнику и возвращает фокус. Подробности — BUILDING_ATLAS.md.

## 27.10.2026 · Из модели к работе с помещением

При ревью обнаружен разрыв: сцена вращалась, но без названий было трудно найти комнату и перейти к источнику. Теперь рядом с моделью два нативных списка — этаж и помещение. Выбор комнаты открывает разрез, приближает её настоящий контур и показывает связанный лист с условным символом, полным именем и исходной площадью либо текущим состоянием/расчётом. На сцене экранные названия не уменьшаются вместе с камерой и не пересекаются; выбранная комната имеет приоритет. На тесном виде все помещения остаются в списке.

«Осмотреть» открывает прежнюю форму ровно этой зоны, «Параметры» — исходный лист комнаты с фокусом на имени. Обзор не отмечает осмотр завершённым. Зона без контура доступна в списке и источниках, но не получает вымышленную форму; приближение отключено.

«Развернуть» оставляет тот же canvas и выбор, отдавая модели окно. Этаж, помещение и слои остаются рядом со сценой. Фон недоступен клавиатуре, Tab замкнут внутри рабочего вида; поиск/осмотр открываются native dialogs выше него. Escape сначала закрывает такое окно, затем модель. Выход возвращает управление к открывшей кнопке; переход к параметрам передаёт фокус исходной комнате. На телефоне проверяются длинное казахское имя, цели 44 px и реальный pinch.

## 27.10.2026 · От пометки к источнику и обратно

Обнаружены два разрыва: переход к параметрам обнулял 3D-ракурс, а источник замечания возвращал только к плоскому плану. Теперь «Исходные записи» выбранной комнаты открывают существующий лист внимания с явным фильтром. Из него можно исправить точную запись либо показать помещение в 3D. Изображение без контура сохраняет свой 2D-маршрут.

После исправления исходной даты запись исчезает сама; отдельного статуса устранения нет. Фильтр комнаты остаётся виден, весь объект доступен крестиком. Возврат из параметров сохраняет рабочий ракурс/выбор/высоту; закрытая сцена освобождает GPU. Сеанс вида ограничен текущими объектом/пользователем и памятью вкладки.

На телефоне лист выбранной комнаты компактнее общего обзора: меньше вступление и отступы, без повторной иллюстрации. Для нуля или одной записи при отсутствии активных поиска/раздела не показываются ненужные фильтры; при нескольких записях или активном фильтре они сохраняются. Имя комнаты, учебный статус, дата отсчёта, причина и исходная запись остаются видимыми. Общий лист не меняется.

## 28.10.2026 · Найти помещение и сразу увидеть его

В результатах поиска запись и расположение имеют самостоятельные кнопки. Слева — полное имя/этаж, модель и переход к исходной форме; справа — «В 3D» либо «План» для существующей геометрии. Зона без привязки сохраняет доступ к параметрам. У оборудования переход относится к комнате, что объясняется рядом с выдачей. Выбор сохраняет текущий слой и ту же сцену; повторный переход снова приближает нужный контур.

Нативный searchbox и список обычных кнопок позволяют выбирать действие пальцем, Tab/Enter или стрелками с настоящим фокусом. Футер и пояснение остаются в native диалоге, прокручивается выдача. Кнопки закрытия/очистки/расположения имеют цели от 44 px, очистка возвращает фокус полю. Выдача загружается по 40 с доступом к следующим записям, в том числе при одинаковых номерах.

Условия запроса об оборудовании проверяются на одной записи. Совпадение номера первого и модели второго больше не даёт ложного результата. Метки изображений на смешанном этаже возвращаются к изображению как из поиска расположения, так и при открытии параметров. Подготовка/проверки — `SPATIAL_SEARCH.md`.
