# Этапы и демонстрация

## Подготовка

Зафиксировать пользователя, визуальное направление, сценарии, поля, источники, границы расчёта, состояние проекта. Выполняется до функциональной разработки.

## Последовательность реализации

1. Каркас рабочего места, два языка, демонстрационная модель школы.
2. Редактирование этажей/зон, контекстные условия и сохранение.
3. Изолированный расчёт с источниками, понятными ограничениями и проверками границ.
4. Схема результатов и разметка своего плана.
5. PDF из конкретного результата, резервный экспорт данных.
6. Проверка мобильного сценария, доступности, ошибок, языков и подготовки к защите.

## Критерии работающего прототипа

- Инспектор открывает объект, видит этажи и выбирает помещение на схеме.
- Изменение площади или условия меняет входные данные и статус результата.
- Тип и количество выводятся по поддержанным правилам; неподдержанный случай объясняется.
- Загрузка плана и размещение метки действительно работают.
- Переключение языка не очищает введённые данные.
- Черновик восстанавливается после перезагрузки либо ошибка сохранения показана явно.
- PDF скачивается, содержит кириллицу/казахские символы, параметры и ссылки на правила.
- Демонстрационные данные обозначены в интерфейсе и отчёте.
- Расчёт количества не выдаётся за проверку расстояний/полную пожарную безопасность объекта.

## Сценарий защиты, около четырёх минут

| Время | Действие |
| --- | --- |
| 0:00–0:20 | Объяснить ручной подбор и перенос исходных данных в отчёт |
| 0:20–0:45 | Инструкция → «Открыть учебный пример»: сразу виден готовый план; вход не нужен |
| 0:45–1:35 | «Рассчитать»: ОП/ОУ и формула. Библиотека 400 → 401 м²: ОП 3 → 4 по профилю прототипа; лаборатория требует отдельного подбора |
| 1:35–2:15 | Готовый блок, изменение размера/поворот. План не перестраивается от изменения расчётной площади |
| 2:15–2:50 | Обход: три ответа, замечание, сохранение/переход; показать учебную запись DEMO-01 |
| 2:50–3:30 | Обновить расчёт, выгрузить и открыть настоящий PDF с планом/записью; показать RU/ҚАЗ |
| 3:30–4:00 | При подготовленной группе показать ответственного/журнал; обозначить экспертную проверку методики перед пилотом |

Подготовленный объект — самостоятельный учебный корпус, не план реальной НИШ. В исходном примере НИШ помещения/площади также синтетические. Не называть результат обследованием школы или завершённым нормативным заключением. Подробный разбор рисков показа — `JURY_REVIEW.md`.

Распределение участников и календарь уточнить с командой; существование этой записи не означает, что ревью уже проведено.

## Резерв и границы расширения

На устройстве должны быть подготовленный объект, резервный JSON и примеры PDF. Не тратить основное время выступления на заполнение пустого шаблона. Реестр CSV можно показать по дополнительному вопросу. Для склада/производства автоматический подбор пока требует отдельного профиля; это видно в интерфейсе, а план и журнал доступны.

Если демонстрируются аккаунты, заранее подготовить собственные учебные аккаунты и группу с объектом; дефолтных паролей в приложении нет. В начале показать ответственного и открыть план, в конце сохранить изменения и показать запись автора в журнале. Регистрацию и передачу приглашения вынести за основной четырёхминутный показ. Для общей работы нужен запущенный Node сервер с постоянной базой; резервная демонстрация на одном ноутбуке запускается `npm run dev`.

Не говорить, что схема НИШ соответствует фактической архитектуре, что завершённая запись подтверждает соответствие, либо что локальное хранение обеспечивает синхронизацию.
